1. خذ نسخة احتياطية من Supabase قبل أي تغيير.
2. افتح مشروع Supabase المرتبط بالموقع، وافحص SQL ثم نفّذ الملف في SQL Editor بحساب المسؤول.
3. تأكد من وجود جدول public.user_favorites وتفعيل RLS والسياسات الثلاث.
4. اختبر بحسابين منفصلين (A وB) أن كل عضو يرى أماكنه فقط؛ انظر للاختبارات أدناه.
5. إذا لم تُنفذ SQL، واجهة المفضلة قد تحفظ محلياً أثناء الجلسة لكنها لن تتزامن سحابياً؛ لا تعتبر التحديث جاهزاً للإنتاج.
6. لا تضع أي مفاتيح service_role داخل JavaScript أو GitHub.

شرح المفضلة:
- اضغط ♡ بجوار اسم المكان لإضافته. اضغط ♥ لإزالته.
- فلتر ❤️ المفضلة ضمن قسم المدينة الحالي يعرض أماكنه المحفوظة فقط.
- التخزين المحلي مؤقت ومخصص لمعرّف المستخدم؛ عند اتصال صالح تتزامن التغييرات إلى Supabase.
- بعد تسجيل الخروج لا تعرض الواجهة مفضلة الحساب السابق.
- انقطاع الإنترنت أثناء جلسة مصدق عليها: الحفظ محلي حتى المزامنة.
- بعد إعادة تحميل الصفحة أو إعادة تشغيل التطبيق دون إنترنت، قد لا يتمكن نظام العضوية الأصلي من التحقق من الجلسة؛ لذا لا يمكن ضمان عرض المفضلة آنذاك. يتطلب هذا تطوير مصادقة بدون اتصال ومراجعة أمنية منفصلة. لا تعد المستخدم بتوفرها الكامل.
- بعض الأماكن القديمة المتكررة ضمن أقسام متعددة تتشارك معرّفاً واحداً للمدينة؛ حُفظ مكان واحد فقط لكل مدينة/معرف.
